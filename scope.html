2.01 Baseline Capture

Phase 0: ~3 Senior Consultant Days

  • Inventory and validation of existing structured data (what's there, what's valid, what's missing)
  • Google Search Console snapshot for an agreed query set
  • Organic ranking baseline for ~10-15 segment-relevant queries
  • Documented behavior of 5 AI engines (ChatGPT, Perplexity, Claude, Gemini, Google AI Overviews) on 10-15 segment queries, with screenshots and transcripts
  • Short baseline write-up for comparison in Phase 3
2.02 Architecture & Route Selection

Phase 1A: ~3 Senior Consultant Days

  • Schema architecture across ~6-7 page-type variants (Hotel root, room/lodging-unit, restaurant, spa/wellness, FAQ, event, breadcrumb enrichment)
  • Entity-graph relationship design defining how types connect across the property's page structure
  • Architectural route recommendation to the technical partner (native JSON-LD vs. CMS extension config vs. hybrid)
  • AI-engine optimization layer: research on best practices, citation-friendly patterns, and llms.txt structure
  • Sign-off gate: client and technical partner approve the architecture before content drafting begins
Deliverable: Architecture document with schema type map, entity relationships, and recommended implementation route. Approved before Phase 1B begins.
2.03 Content & Specification

Phase 1B: ~5 Senior Consultant Days

  • Bilingual content values (DE + EN) for every schema block; every block has text copy that needs drafting in two languages
  • Page-by-page specification document, JSON-LD blocks ready to implement per the approved architecture
  • llms.txt and llms-full.txt drafting, citation-friendly content recommendations
  • Coordination with the technical partner on implementation specifics as they arise from content
Iteration clause: Up to one architectural revision pass is included if content drafting reveals structural gaps in the 1A schema design. Revisions beyond one pass are scoped as a separate addendum.
2.04 Implementation Coordination

Phase 2: ~2 Senior Consultant Days

  • Handoff session with technical partner on the finalized spec
  • Async QA support during implementation, up to 3 rounds of review (clarifications, partial checks)
  • Final QA of deployed markup against the spec; validation pass DE + EN, sample checks across page types
2.05 Validation & Handover

Phase 3: ~2 Senior Consultant Days

  • Re-run the same AI-engine query set from Phase 0 against the live, marked-up site, using the same engines and the same queries, with screenshots and transcripts (3-4 months after Phase 0)
  • Rich Results Test and Schema.org Validator full-site pass (DE + EN)
  • Comparison report against Phase 0 baseline
  • Living-spec handover documentation that the client can extend to future pages
2.06 Parallel Track — Markdown Site

Parallel Track: Machine-Readable Markdown Mirror

Alongside the schema phases above, a parallel track designs and specifies a machine-readable markdown mirror of the site optimized for LLM and AI-engine consumption.

  • Runs in parallel starting after Phase 1A sign-off — the schema architecture decisions gate the markdown structure
  • Detailed on the Markdown Site page (page 03)
  • Depends on Phase 1A architecture decisions — entity relationships, page-type taxonomy, and route selection inform the markdown hierarchy
  • Technical implementation (pipeline build) is optionally subcontracted or handled by the client's technical partner
  • Validation (MD-3) runs alongside Phase 3 using the same methodology and engines from the baseline query set
Track 2 leverages Track 1's architecture. Together they give AI engines both structured descriptions (schema) and readable content (markdown mirror).
